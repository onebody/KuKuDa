## 1. 文本输入节点（TextInputNode）

### 1.1 功能规格

**详细功能描述**：  
文本输入节点是工作流中最基础的**源节点**，用户可在节点内部直接输入任意文本内容，该文本将作为字符串输出，供下游处理节点（如 AI 绘图节点、文本输出节点）使用。

**用户操作流程**：
1. 用户从节点面板拖拽“文本输入节点”到画布
2. 节点创建后，用户点击节点主体区域的多行文本框
3. 用户输入或粘贴文本内容（支持任意长度，但建议不超过 10000 字符）
4. 用户点击文本框外部或按下 `Ctrl+Enter` 保存内容
5. 节点右下角的输出句柄变为激活状态（蓝色），表示已有输出数据
6. 用户可将输出句柄连接到下游处理节点的输入句柄

**界面元素详细说明**：
- **节点标题栏**：显示“📝 文本输入”图标和名称，背景色为深色（#1e1e1e）
- **主体区域**：一个多行文本输入框（`<textarea>`），占据节点大部分区域
  - 默认高度：100px，可拖拽右下角调整高度（最大 400px）
  - 占位符文本：“请输入文本内容...”
  - 边框：无边框，背景透明，文字颜色 #fff
  - 内边距：8px
- **输出句柄**：右下角，圆形，标注“文本输出”，默认灰色，有输出时变为蓝色
- **节点状态指示**：无输出时边框为灰色，有输出时边框为绿色（表示空闲但有输出）

**交互细节**：
- **点击文本框**：光标聚焦，显示闪烁光标，背景略变亮（#2a2a2a）
- **输入过程中**：实时自动保存（debounce 500ms），无需手动保存
- **拖拽调整高度**：鼠标悬停文本框右下角，光标变为 `nwse-resize`，拖拽调整高度
- **悬停输出句柄**：显示 tooltip：“文本输出（字符串）”
- **连接成功后**：边显示为蓝色，输出句柄锁定为蓝色

### 1.2 数据结构详细定义

**输入数据格式**（从上游接收）：无（源节点，无输入句柄）

**输出数据格式**（向下游发送）：
```typescript
interface TextInputNodeOutput {
  text: string;  // 用户输入的文本内容（必填，可为空字符串）
}
```

**配置参数**（用户可设置的参数）：无（文本输入框即为全部配置）

**数据验证规则**：
- `text` 字段：允许空字符串，最大长度建议 10000 字符（超过时截断并提示）

### 1.3 用户故事

| 编号 | 用户故事 | 场景类型 |
|------|----------|----------|
| US-001 | 作为一名 AI 绘画爱好者，我想要输入绘画提示词，以便下游 AI 绘图节点可以读取并生成图片 | 正常场景 |
| US-002 | 作为一名内容创作者，我想要输入一段文章草稿，以便下游文本输出节点可以显示最终文本 | 正常场景 |
| US-003 | 作为一名测试人员，我想要测试空文本输入的情况，以便确保下游节点能正确处理空字符串 | 异常场景 |

### 1.4 验收标准

**功能验收标准**：
- [ ] 用户可以在文本框中输入任意文本内容
- [ ] 输入内容实时保存（debounce 500ms）
- [ ] 节点输出句柄在有内容时激活（变为蓝色）
- [ ] 下游节点可以正确读取 `text` 字段

**UI/UX 验收标准**：
- [ ] 文本框占位符正确显示“请输入文本内容...”
- [ ] 拖拽调整高度时，文本框高度实时变化
- [ ] 输出句柄悬停时显示正确 tooltip

**性能验收标准**：
- [ ] 输入 10000 字符时，输入无卡顿（debounce 后保存）
- [ ] 节点渲染时间 < 100ms

**边界条件验收标准**：
- [ ] 输入为空字符串时，输出 `{ text: "" }`，下游节点可正常读取
- [ ] 输入超长文本（>10000 字符）时，截断并提示“文本过长，已截断至10000字符”

### 1.5 与其他节点的交互

**可以作为哪些节点的上游？**
- ✅ AI 绘图节点（读取 `text` 作为 prompt）
- ✅ 文本输出节点（读取 `text` 作为显示内容）
- ✅ 技能节点（如果技能需要 `prompt` 参数，可映射 `text`）

**可以从哪些节点接收输入？**
- ❌ 无（源节点，无输入句柄）

**数据传递的具体格式？**
- 通过 React Flow 的边（edge）传递，数据为 `{ text: string }`

## 2. 单图片输入节点（SingleImageInputNode）

### 2.1 功能规格

**详细功能描述**：  
单图片输入节点允许用户选择一张本地图片（或粘贴剪贴板图片），上传后生成图片 URL，输出给下游处理节点。支持点击选择、拖拽上传、Ctrl+V 粘贴三种方式。

**用户操作流程**：
1. 用户从节点面板拖拽“单图片输入节点”到画布
2. 节点创建后，显示“点击选择图片”按钮
3. 用户点击按钮，弹出**图片选择弹窗**（深色主题）
4. 用户在弹窗中点击“选择文件”按钮，打开文件选择器（仅允许选择图片文件）
5. 用户选择一张图片，点击“打开”
6. 图片上传到 MinIO 对象存储，生成 URL
7. 弹窗关闭，节点显示图片缩略图和文件名
8. 节点输出句柄激活（蓝色），输出 `{ imageUrl: string }`

**界面元素详细说明**：
- **节点标题栏**：显示“🖼️ 单图片输入”图标和名称
- **主体区域**（未选择图片）：显示“点击选择图片”按钮（居中，带图标）
- **主体区域**（已选择图片）：显示图片缩略图（最大 180x100px，等比例缩放）、文件名（12px 字体，截断显示）、文件大小（10px 灰色字体）
- **输出句柄**：右下角，标注“图片输出”，默认灰色，有输出时变为蓝色
- **重新选择按钮**：图片上方悬浮显示“重新选择”按钮（悬停时显示）

**交互细节**：
- **点击“点击选择图片”按钮**：弹出图片选择弹窗
- **拖拽图片到节点**：直接触发上传，显示上传进度条
- **Ctrl+V 粘贴**：如果剪贴板包含图片，自动触发上传
- **悬停图片缩略图**：显示放大预览（tooltip 或 popover）
- **点击“重新选择”按钮**：重新弹出图片选择弹窗

### 2.2 数据结构详细定义

**输入数据格式**（从上游接收）：无（源节点，无输入句柄）

**输出数据格式**（向下游发送）：
```typescript
interface SingleImageInputNodeOutput {
  imageUrl: string;   // 图片的 URL 地址（必填）
  fileName: string;    // 原始文件名（必填）
  fileSize: number;    // 文件大小（字节，必填）
}
```

**配置参数**：无（图片选择弹窗中的操作为全部配置）

**数据验证规则**：
- `imageUrl`：必须是有效的 URL 格式（以 `http://` 或 `https://` 开头）
- `fileName`：不能为空字符串
- `fileSize`：必须 > 0

### 2.3 用户故事

| 编号 | 用户故事 | 场景类型 |
|------|----------|----------|
| US-004 | 作为一名设计师，我想要上传一张参考图片，以便下游 AI 绘图节点可以基于该图片生成变体 | 正常场景 |
| US-005 | 作为一名用户，我想要通过拖拽方式上传图片，以便更快捷地完成图片输入 | 正常场景 |
| US-006 | 作为一名用户，我想要粘贴剪贴板中的图片，以便无需保存文件即可上传 | 正常场景 |

### 2.4 验收标准

**功能验收标准**：
- [ ] 用户可以点击按钮选择图片文件
- [ ] 用户可以拖拽图片文件到节点上传
- [ ] 用户可以 Ctrl+V 粘贴剪贴板图片
- [ ] 上传成功后，节点显示图片缩略图和文件名
- [ ] 输出句柄激活，下游节点可读取 `imageUrl`

**UI/UX 验收标准**：
- [ ] 图片选择弹窗为深色主题（#1e1e1e）
- [ ] 拖拽上传时，节点显示上传进度条

**性能验收标准**：
- [ ] 上传 10MB 图片时，上传时间 < 5 秒（取决于网络速度）
- [ ] 图片缩略图加载时间 < 1 秒

**边界条件验收标准**：

**可以从哪些节点接收输入？**

## 3. 多图片输入节点（MultiImageInputNode）

### 3.1 功能规格

**详细功能描述**：  
多图片输入节点允许用户批量选择最多 20 张图片，自动按上传顺序编号 1-20，输出图片 URL 数组，供下游处理节点使用。支持批量选择、拖拽批量上传、连续 Ctrl+V 粘贴。

**用户操作流程**：
1. 用户从节点面板拖拽“多图片输入节点”到画布
2. 节点创建后，显示“上传图片”按钮
3. 用户点击按钮，弹出**批量上传图片弹窗**（深色主题）
4. 用户点击弹窗右上角“上传图片”按钮，打开文件选择器（允许多选）
5. 用户选择多张图片（最多 20 张），点击“打开”
6. 图片逐一上传到 MinIO，生成 URL，并按顺序编号 1-20
7. 弹窗中央区域显示图片预览网格（每张图片显示缩略图、编号、文件名）
8. 用户点击弹窗底部“确认”按钮，弹窗关闭
9. 节点显示图片数量和预览网格，输出句柄激活，输出 `{ imageUrls: string[], images: Array<{ id, url, fileName, fileSize }> }`

**界面元素详细说明**：
- **节点标题栏**：显示“🖼️🖼️ 多图片输入”图标和名称
- **主体区域**（未上传图片）：显示“上传图片”按钮（居中，带图标）、提示文字“支持最多20张图片（自动编号1-20）”
- **主体区域**（已上传图片）：显示图片数量文字（如“已上传 5 张图片”）、图片预览网格（每行 4 张，缩略图 60x60px）
- **输出句柄**：右下角，标注“图片输出（数组）”，默认灰色，有输出时变为蓝色
- **查看全部按钮**：图片网格上方显示“查看全部”按钮，点击弹出大图预览弹窗

**交互细节**：
- **点击“上传图片”按钮**：弹出批量上传弹窗
- **拖拽多张图片到节点**：直接触发批量上传，显示上传进度条（每张图片单独显示进度）
- **连续 Ctrl+V 粘贴**：每次粘贴，自动上传剪贴板图片，并追加到图片数组
- **自动编号**：按上传顺序编号 1-20，编号不可手动修改
- **超过 20 张时**：提示“最多支持20张图片”，拒绝继续上传
- **清空按钮**：弹窗右上角“清空”按钮，点击清空所有已上传图片
- **删除单张图片**：鼠标悬停图片缩略图，显示“删除”按钮，点击删除该图片，后续编号自动重排

### 3.2 数据结构详细定义

**输入数据格式**（从上游接收）：无（源节点，无输入句柄）

**输出数据格式**（向下游发送）：
```typescript
interface MultiImageInputNodeOutput {
  imageUrls: string[];  // 图片 URL 数组（必填，按编号顺序排列）
  images: Array<{
    id: number;        // 编号 1-20（必填）
    url: string;       // 图片 URL（必填）
    fileName: string;  // 文件名（必填）
    fileSize: number;  // 文件大小（字节，必填）
  }>;
  maxCount: number;    // 最大数量，固定为 20
}
```

**配置参数**：无（图片选择弹窗中的操作为全部配置）

**数据验证规则**：
- `imageUrls`：数组长度必须 ≤ 20
- `images`：每个元素的 `id` 必须唯一，且在 1-20 范围内
- `images`：每个元素的 `url` 必须是有效的 URL 格式

## 4. 单文件输入节点（SingleFileInputNode）

### 4.1 功能规格

**详细功能描述**：  
单文件输入节点允许用户选择单个文件（任意类型），上传后生成文件 URL，输出给下游处理节点。功能与单图片输入节点类似，但支持所有文件类型。

**用户操作流程**：
1. 用户从节点面板拖拽“单文件输入节点”到画布
2. 节点创建后，显示“点击选择文件”按钮
3. 用户点击按钮，弹出**文件选择弹窗**（深色主题）
4. 用户在弹窗中点击“选择文件”按钮，打开文件选择器（允许选择所有文件类型）
5. 用户选择一个文件，点击“打开”
6. 文件上传到 MinIO，生成 URL
7. 弹窗关闭，节点显示文件图标、文件名和文件大小
8. 节点输出句柄激活，输出 `{ fileUrl: string, fileInfo: { fileName, fileSize, fileType } }`

**界面元素详细说明**：
- **节点标题栏**：显示“📄 单文件输入”图标和名称
- **主体区域**（未选择文件）：显示“点击选择文件”按钮（居中，带图标）
- **主体区域**（已选择文件）：显示文件图标（根据文件类型显示不同图标）、文件名（12px 字体，截断显示）、文件大小（10px 灰色字体）、文件类型（10px 灰色字体，如“application/pdf”）
- **输出句柄**：右下角，标注“文件输出”，默认灰色，有输出时变为蓝色

**交互细节**：
- **点击“点击选择文件”按钮**：弹出文件选择弹窗

## 6. AI 绘图节点（AIImageNode）

### 6.1 功能规格

**详细功能描述**：  
AI 绘图节点是**处理节点**，用户可以输入绘画提示词（prompt），或者连接上游文本输入节点读取 prompt，调用 AI 绘图接口生成图片，并输出图片 URL。

**用户操作流程**：
1. 用户从节点面板拖拽“AI 绘图节点”到画布
2. 节点创建后，显示 prompt 输入框（textarea）和“生成”按钮
3. **场景 A（无上游连接）**：用户在 prompt 输入框中输入提示词，点击“生成”按钮
4. **场景 B（有上游连接）**：用户将上游文本输入节点的输出句柄连接到 AI 绘图节点的输入句柄
5. 上游节点输出数据后，AI 绘图节点自动读取 `text` 字段作为 prompt
6. 节点状态变为“执行中”（蓝色边框，显示进度条）
7. 调用后端 AI 绘图代理接口（`POST /api/ai/image-generation`）
8. 生成完成后，节点显示生成的图片缩略图，状态变为“成功”（绿色边框）
9. 节点输出句柄激活，输出 `{ imageUrl: string }`

**界面元素详细说明**：
- **节点标题栏**：显示“🎨 AI 绘图”图标和名称

- **主体区域**（无上游连接）：显示 prompt 输入框（textarea，占位符“请输入绘画提示词...”）、生成按钮（“生成”，带图标）

- **主体区域**（生成完成后）：显示生成的图片缩略图（最大 180x100px）、图片 URL（12px 字体，截断显示）、“重新生成”按钮
- **右侧输出句柄**：标注“图片输出”，默认灰色，有输出时变为蓝色
- **状态指示**：空闲（灰色边框）、执行中（蓝色边框 + 进度条）、成功（绿色边框）、失败（红色边框 + 错误信息 tooltip）

**交互细节**：
- **输入 prompt 后点击“生成”**：验证 prompt 不为空，然后调用 AI 接口
- **连接上游节点后**：自动读取上游 `text` 作为 prompt，prompt 输入框变为只读
- **断开上游连接后**：prompt 输入框恢复可编辑状态

- **生成完成后**：显示图片缩略图，“生成”按钮变为“重新生成”按钮
- **生成失败后**：显示红色边框，悬停时显示错误信息 tooltip，“重新生成”按钮可用

### 8.1 功能规格

**详细功能描述**：  
技能节点是**处理节点**，用户可以配置一个技能（Skill），节点根据技能的 input schema 动态生成输入表单，调用技能接口，输出执行结果。技能是扩展工作流能力的方式，用户可以安装自定义技能。

**用户操作流程**：
1. 用户从节点面板拖拽“技能节点”到画布
2. 节点创建后，显示“配置技能”按钮
3. 用户点击按钮，弹出**技能配置弹窗**（深色主题）
4. 用户在弹窗中选择一个技能（从技能列表中选择）
5. 弹窗根据技能的 input schema 动态生成输入参数表单
6. 用户填写输入参数（或使用上游节点的输出数据自动填充）
7. 用户点击“保存”按钮，弹窗关闭
8. 节点显示技能名称和已配置的输入参数（只读）
9. 用户点击节点上的“执行”按钮，调用技能接口
10. 执行完成后，节点显示执行结果，输出句柄激活，输出 `{ result: any }`

**界面元素详细说明**：
- **节点标题栏**：显示“🔧 技能：{技能名称}”图标和名称（如果已配置技能）
- **左侧输入句柄**：多个输入句柄（根据技能的 input schema 动态生成），标注输入参数名称
- **主体区域**（未配置技能）：显示“配置技能”按钮（居中，带图标）
- **主体区域**（已配置技能）：显示技能名称、已配置的输入参数（只读，每个参数一行，显示参数名和值）、执行按钮（“执行”，带图标）
- **右侧输出句柄**：根据技能的 output schema 动态生成，标注输出参数名称
- **状态指示**：空闲（灰色边框）、执行中（蓝色边框 + 进度条）、成功（绿色边框）、失败（红色边框 + 错误信息 tooltip）

**交互细节**：
- **点击“配置技能”按钮**：弹出技能配置弹窗
- **选择技能后**：弹窗动态生成输入参数表单（根据技能的 input schema）
- **填写输入参数时**：可以使用上游节点的输出数据自动填充（如果连接了上游节点）
- **点击“保存”按钮**：保存技能配置，弹窗关闭
- **点击“执行”按钮**：调用技能接口，显示执行进度
- **执行完成后**：显示执行结果（根据 output schema 格式化显示）

### 8.2 数据结构详细定义

**输入数据格式**（从上游接收）：
```typescript
interface SkillNodeInput {
  [key: string]: any;  // 根据技能的 input schema 确定，每个输入参数对应一个字段
}
```

**输出数据格式**（向下游发送）：
```typescript
interface SkillNodeOutput {
  result: any;  // 技能执行结果（根据技能的 output schema 确定）
}
```

**配置参数**（用户可设置的参数）：
- `skillId`（string）：技能 ID（必填）
- `skillName`（string）：技能名称（必填）
- `inputParams`（object）：输入参数（根据技能的 input schema 确定，每个参数一个字段）

**数据验证规则**：
- `skillId` 和 `skillName` 必须存在（即必须配置技能）
- `inputParams` 中的每个参数，必须符合技能的 input schema 定义的类型和格式

- [ ] 输出句柄激活，下游节点可读取 `result`

**UI/UX 验收标准**：
- [ ] 技能配置弹窗为深色主题（#1e1e1e）
- [ ] 输入参数表单根据 schema 动态生成（文本输入框、数字输入框、下拉选择等）

**性能验收标准**：
- [ ] 调用技能接口后，30 秒内返回结果（取决于技能接口速度）
- [ ] 动态生成输入参数表单，耗时 < 500ms

**边界条件验收标准**：
- [ ] 未配置技能时，点击“执行”按钮，提示“请先配置技能”
- [ ] 技能接口调用失败时，节点显示红色边框和错误信息
- [ ] 技能接口超时（>30 秒）时，节点显示“执行超时”错误信息

### 8.5 与其他节点的交互

**可以作为哪些节点的上游？**
- ✅ 文本输出节点（读取 `result`，如果 `result` 是字符串）
- ✅ 其他技能节点（读取 `result`，如果后续技能需要该数据）

**可以从哪些节点接收输入？**
- ✅ 文本输入节点（如果技能需要 `prompt` 参数，可映射 `text`）
- ✅ AI 绘图节点（如果技能需要 `imageUrl` 参数，可映射 `imageUrl`）
- ✅ 其他技能节点（读取上游技能的输出结果）

**数据传递的具体格式？**
- 输入：通过 React Flow 的边（edge）传递，数据为 `{ [key: string]: any }`（根据 input schema 确定）
- 输出：通过 React Flow 的边（edge）传递，数据为 `{ result: any }`（根据 output schema 确定）

## 9. 节点交互规则汇总

### 9.1 数据流动规则

**核心原则**：**被动读取，不主动触发**。

**规则详解**：
1. 处理节点只读取**已有输出结果**的上游节点数据，不会主动触发上游节点执行。
2. 如果上游节点无输出，处理节点显示“等待上游数据...”（黄色边框），暂停执行。
3. 一旦上游节点有输出，处理节点自动触发执行。

**实现方式**：
- 前端使用 Zustand 派生状态缓存上游数据
- 处理节点订阅上游节点的输出状态，一旦变化，自动触发执行

### 9.2 输入合并策略

当一个处理节点有多个上游节点时，需要将多个输入源的数据合并。采用**追加拼接**策略。

**文本合并策略**：按顺序拼接，以换行符（`\n`）分隔。
- 示例：上游节点 A 输出 `{ text: "Hello" }`，上游节点 B 输出 `{ text: "World" }`，合并后输入到处理节点：`"Hello\nWorld"`

**图片/文件 URL 合并策略**：数组合并。
- 示例：上游节点 A 输出 `{ imageUrls: ["url1", "url2"] }`，上游节点 B 输出 `{ imageUrls: ["url3", "url4"] }`，合并后输入到处理节点：`["url1", "url2", "url3", "url4"]`

**多种类型合并策略**：按类型分别处理。
- 示例：上游节点 A（文本输入）输出 `{ text: "Hello" }`，上游节点 B（单图片输入）输出 `{ imageUrl: "url1" }`，合并后输入到处理节点：`{ texts: ["Hello"], imageUrls: ["url1"] }`

### 9.3 节点连接规则

**允许的连接**：
- ✅ 源节点的输出句柄 → 处理节点的输入句柄
- ✅ 处理节点的输出句柄 → 另一个处理节点的输入句柄（如果数据类型兼容）
- ✅ 处理节点的输出句柄 → 终端节点（文本输出节点）的输入句柄

**禁止的连接**：
- ❌ 终端节点（文本输出节点）的输出句柄 → 任何节点的输入句柄（因为终端节点无输出句柄）
- ❌ 数据类型不兼容的连接（如：图片输出 → 文本输入），系统应提示“数据类型不兼容”
