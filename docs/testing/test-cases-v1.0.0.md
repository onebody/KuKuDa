## 1. 测试用例概述

### 1.1 测试用例编写原则

1. **完整性**：覆盖所有功能点和非功能需求
2. **有效性**：每个测试用例都有明确的预期结果
3. **可执行性**：测试步骤清晰、可操作
4. **可重复性**：测试结果可复现
5. **独立性**：每个测试用例独立执行，不依赖其他测试用例

### 1.2 测试用例设计方法

1. **等价类划分**：输入有取值范围的字段
2. **边界值分析**：边界条件（如文件数量、大小限制）
3. **场景法**：业务流程测试（如完整工作流执行）
4. **状态转换法**：节点状态变化（等待 → 执行中 → 成功/失败）
5. **错误推测法**：基于经验推测易错点

### 1.3 测试用例优先级定义

| 优先级 | 描述 | 示例 |
|--------|------|------|
| **高** | 核心功能、高频使用场景 | 节点创建、连接、数据流动 |
| **中** | 重要功能、中频使用场景 | 文件上传、AI 绘图 |
| **低** | 边缘功能、低频使用场景 | UI 样式、Tooltip 提示 |
